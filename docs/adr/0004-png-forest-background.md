# App-wide PNG forest background (replaces the SVG leaf backdrop)

The Parrot MBTI web adopts a single **PNG-based, layered mobile forest** as the
app-wide backdrop behind every surface (Intro / Test / Result / Dex). It is
mounted once via `<MobileForestBackground>` in `app/layout.tsx` as a
`position: fixed; inset: 0; z-index: -1` layer, so the same forest world is shared
by all routes and **stays pinned to the viewport on scroll** (only page content
scrolls above it).

This **replaces** the prior backdrop, which was two pieces: the `<LeafField>`
faceted low-poly **SVG** leaf layer and the `body` cream **radial-gradient washes**
in `app/globals.css`. Both are removed. The intro's separate in-content forest
band (`.hero-art`, `/forest.webp`) is also removed — the background now carries it.

The assets are illustrated PNGs generated by design and served as static files
from `public/assets/mbti/`. Decorative-only; referenced as `/assets/mbti/<name>.png`.

## Layers

Painted low → high (DOM order inside the fixed container): main base
(`forest-mobile-base`) → side decals (monstera / palm / general leaf, hanging vine,
rock cluster, mushroom-flower cluster) → top-canopy + bottom-ground overlays →
light particles → **cream legibility veil** → page content.

## Considered Options

- **Layered PNG forest, single fixed layer (chosen)** — matches the supplied art,
  one shared world across the funnel, zero JS (server component), trivially
  extended later (srcset via `<picture>`, per-route veil).
- **Keep the SVG leaf backdrop** — lighter, but does not match the delivered art
  direction and lacks the depth/atmosphere of the illustrated forest.
- **Apply the forest only on Intro** — lower risk, but leaves the funnel visually
  inconsistent; the product owner chose a global world.

## Consequences

- **Relationship to ADR-0001.** ADR-0001 chose a cream-parchment world and (issue
  #03) a deliberately **calm** Test surface ("editorial trail"). A full forest
  behind cream cards risks legibility. This is reconciled by a **cream veil layer**
  (`--forest-veil-strength`) that washes the central content band so headings,
  cards, and CTAs stay readable on every surface; the calm intent of the Test
  screen is preserved by that veil rather than by a flat backdrop. ADR-0001 is not
  reversed — only the backdrop medium changes (SVG/gradient → PNG forest).
- **Single fixed theme is kept.** No `prefers-color-scheme` dark mode; the shared
  result card looks identical for every viewer.
- **PNG weight.** The base PNG is ~1.8 MB and the full decorative set ~3.5 MB. To
  protect mobile LCP, only the base loads eagerly (`fetchpriority="high"`); canopy,
  ground, particles, and all decals are `loading="lazy"`. Single resolution per
  asset; **no srcset** (the layout is structured so a `<picture>`/srcset can be
  added later without markup churn). A future WebP variant for the base is the
  obvious next optimization if LCP needs it.
- **Missing assets.** The brief expected a "tree branch" and a "bush cluster" PNG;
  neither was delivered, so both are omitted (no broken paths). They can be added
  to the `DECALS` list in `components/mobile-forest-background.tsx` when available.
- **Accessibility.** All forest images are decorative: `alt=""`, `aria-hidden`,
  `pointer-events: none`, `user-select: none`. The container is `pointer-events:
none` and sits at `z-index: -1`, so it never intercepts interaction.
- **Reversibility.** Mechanism is isolated to one component + its CSS; the body
  keeps a warm cream fallback color, so disabling the forest falls back cleanly.
