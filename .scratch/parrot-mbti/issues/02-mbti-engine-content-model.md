## What to build

앵BTI **산출 엔진**과 이를 구동하는 **콘텐츠 데이터 모델**. UI가 아닌
순수 로직/데이터 레이어이므로 03(디자인)과 무관하게 진행한다.

- 정식 4축(E·I, S·N, T·F, J·P) 16유형. **축당 3문항, 총 12문항**으로 동점(타이)을 원천 차단한다.
- 각 선택지(Choice)는 정확히 한 축의 한쪽 글자에 1점을 가중한다. 축별 다수 글자가 그 축의 결과 글자가 되고, 4글자를 결합해 유형 코드를 만든다.
- 산출은 **부수효과 없는 순수 함수**로 분리한다:

    ```
    computeResult(answers) -> { type: TypeCode, axisScores: Record<Axis, {left:number, right:number}> }
    // 12개 답안 → 축별 집계 → 각 축 다수 글자 결합 → 4글자 TypeCode
    // 축당 문항이 홀수(3)이므로 타이 불가. 답안 누락/불완전 시 산출을 거부한다.
    ```

- **콘텐츠 데이터 모듈**을 코드와 분리한다: 12문항(질문 문구, 두 선택지, 각 선택지의 축/방향) + 16유형(유형명·리포트 카피·대표 이미지 키). 이 단계의 카피·이미지는 플레이스홀더여도 되며, 구조와 축 매핑이 정확해야 한다(실제 콘텐츠는 12에서 확정).
- 01의 스텁 `computeResult`를 이 실제 구현으로 교체한다.

## Acceptance criteria

- [ ] 12문항·4축 데이터가 정의되고, 각 선택지가 축/방향에 매핑된다.
- [ ] 알려진 선택지 조합으로 플로우를 끝까지 구동하면 결과 화면에 기대 유형이 표시된다(E2E로 확인).
- [ ] 16개 유형이 모두 도달 가능한 매핑이다.
- [ ] 답안이 불완전하면 결과를 산출하지 않는다(조용히 소실되지 않음).
- [ ] 문항/유형 콘텐츠는 코드와 분리된 데이터로 교체 가능하다.
- [ ] `yarn build`/`yarn type-check` 통과.
