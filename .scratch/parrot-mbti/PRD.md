# PRD: 앵무새 MBTI 테스트 (Parrot MBTI)

Status: ready-for-agent

> 버디버드(BuddyBird) 앱 유입을 위한 바이럴 웹. 사용자가 자신의 앵무새를 관찰한
> 결과를 선택지로 입력하면 앵무새의 MBTI를 도출하고, 결과 카드를 인스타로 공유하게
> 하여 최종적으로 버디버드 앱 설치로 유도한다.

## 용어 (Glossary)

이 문서에서 쓰는 도메인 용어다. 추후 `CONTEXT.md`로 승격할 후보다.

- **안내 페이지 (Intro)**: 첫 진입 화면. 서비스 소개 + 유형별 앵무새 이미지 캐러셀 + "테스트 시작하기" CTA.
- **문항 페이지 (Test)**: 2지선다 문항을 순차 제시하는 화면. 선택 시 자동으로 다음 문항으로 전환.
- **결과 페이지 (Result)**: 도출된 MBTI 유형 + 리포트 + 유형 이미지 + 사진 촬영/공유/다시하기.
- **문항 (Question)**: 두 개의 **선택지(Choice)** 를 가진 질문. 각 선택지는 하나의 **축(Axis)** 한쪽으로 가중된다.
- **축 (Axis)**: MBTI 4개 축 — E·I, S·N, T·F, J·P.
- **유형 (Type)**: 4축 조합으로 도출된 16개 결과 중 하나 (예: `ENFP`).
- **결과 카드 (Result Card)**: 인스타 공유용으로 생성되는 정사각 이미지. 앵무새 사진 + 유형 + 카피 + 버디버드 브랜딩/CTA.
- **앱 유도 (App CTA)**: 버디버드 앱 설치 유도 링크. 딥링크 서비스 + 스토어 링크.

## Problem Statement

앵무새 보호자(반려인)는 자기 새의 성격을 재미있게 표현하고 친구들과 공유하고 싶지만,
마땅한 방법이 없다. 버디버드 팀 입장에서는 앵무새 보호자라는 타깃에게 앱을 알릴
저비용·고확산 채널이 필요하다. 광고는 비싸고, 직접적인 앱 홍보는 전환이 낮다.

## Solution

보호자가 자기 앵무새를 관찰한 내용을 2지선다로 답하면 앵무새의 MBTI를 도출해 주는
가벼운 모바일 웹을 제공한다. 결과를 받은 사용자는 자기 앵무새 사진을 찍어 결과 카드로
만들고 인스타에 공유한다. 공유된 카드와 결과 페이지 곳곳의 CTA가 새로운 사용자를
다시 테스트로, 그리고 궁극적으로 버디버드 앱 설치로 끌어들이는 바이럴 루프를 만든다.

사용자 여정: **안내 → 문항(2지선다, 자동 진행) → 결과(유형 리포트 + 사진 촬영 + 공유) → 앱 설치**.

## User Stories

### 안내 페이지

1. 앵무새 보호자로서, 첫 화면에서 이 테스트가 무엇인지 한눈에 이해하고 싶다. 그래야 시작할지 판단할 수 있다.
2. 보호자로서, 중앙 하단의 "테스트 시작하기" 버튼을 눌러 즉시 문항으로 진입하고 싶다. 그래야 망설임 없이 시작할 수 있다.
3. 보호자로서, 화면 가운데에서 유형별 앵무새 이미지가 자동 슬라이드로 넘어가는 것을 보고 싶다. 그래야 결과물이 기대되어 시작 동기가 생긴다.
4. 보호자로서, 캐러셀이 자동으로 넘어가더라도 좌우로 직접 넘겨볼 수 있길 원한다. 그래야 보고 싶은 유형을 바로 볼 수 있다.
5. 모션에 민감하거나 `prefers-reduced-motion`을 켠 사용자로서, 자동 슬라이드가 멈추거나 약화되길 원한다. 그래야 어지럽지 않게 이용할 수 있다.
6. 잠재 사용자로서, 안내 페이지에서도 버디버드 앱을 알 수 있는 진입점을 보고 싶다. 그래야 테스트를 안 하더라도 앱으로 갈 수 있다.
7. 모바일 사용자로서, 세로 화면(모바일)에서 레이아웃이 깨지지 않고 보기 좋길 원한다. 대부분의 유입이 모바일이기 때문이다.

### 문항 페이지

8. 보호자로서, 한 번에 하나의 문항과 두 개의 선택지만 보고 싶다. 그래야 집중해서 빠르게 답할 수 있다.
9. 보호자로서, 선택지를 고르면 별도 "다음" 버튼 없이 자동으로 다음 문항으로 넘어가길 원한다. 그래야 빠른 호흡으로 끝낼 수 있다.
10. 보호자로서, 문항이 전환될 때 풀숲을 헤치고 이동하는 듯한 애니메이션을 보고 싶다. 그래야 앵무새 테마의 몰입감이 생긴다.
11. 보호자로서, 지금 몇 번째 문항인지(진행률)를 알고 싶다. 그래야 얼마나 남았는지 가늠할 수 있다.
12. 보호자로서, 직전 문항으로 돌아가 답을 바꾸고 싶다. 그래야 실수로 누른 선택을 고칠 수 있다.
13. 보호자로서, 마지막 문항을 답하면 자동으로 결과 페이지로 이동하길 원한다. 그래야 흐름이 끊기지 않는다.
14. 모션 민감 사용자로서, 전환 애니메이션이 줄거나 즉시 전환되길 원한다(reduced-motion). 그래야 불편 없이 진행한다.
15. 보호자로서, 중간에 새로고침해도 진행 상태가 합리적으로 유지되거나(또는 명확히 처음부터) 동작하길 원한다. 그래야 답이 날아가 당황하지 않는다.

### 결과 페이지 — 리포트

16. 보호자로서, 내 선택을 바탕으로 도출된 우리 새의 MBTI 유형을 보고 싶다. 그것이 이 테스트의 핵심 보상이기 때문이다.
17. 보호자로서, 유형에 맞는 설명(성격 리포트)을 읽고 싶다. 그래야 결과에 공감하고 공유하고 싶어진다.
18. 보호자로서, 유형별로 다르게 설정된 앵무새 대표 이미지를 보고 싶다. 그래야 결과가 더 그럴듯하고 귀엽게 느껴진다.
19. 보호자로서, "다시하기" 버튼으로 처음부터 다시 테스트할 수 있길 원한다. 그래야 다른 답으로 또는 다른 새로 재시도할 수 있다.
20. 보호자로서, 결과 페이지에서 버디버드 앱 설치 CTA를 명확히 보고 싶다. 그래야 더 알아보고 싶을 때 바로 앱으로 갈 수 있다.

### 결과 페이지 — 사진 촬영 & 공유

21. 보호자로서, 결과 페이지에서 우리 새 사진을 그 자리에서 촬영할 수 있길 원한다. 그래야 결과 카드에 진짜 우리 새를 담을 수 있다.
22. 보호자로서, 카메라로 새로 찍는 대신 갤러리에 이미 있는 사진을 고를 수도 있길 원한다. 그래야 잘 나온 사진을 쓸 수 있다.
23. 보호자로서, 선택/촬영한 사진이 결과 카드에 어떻게 들어가는지 미리보기로 확인하고 싶다. 그래야 마음에 드는지 보고 다시 찍을 수 있다.
24. 보호자로서, "공유하기"를 누르면 인스타 등으로 바로 공유되길 원한다. 그래야 친구들에게 손쉽게 자랑할 수 있다.
25. 보호자로서, 공유되는 이미지가 인스타에 어울리는 카드(유형, 카피, 우리 새 사진, 버디버드 브랜딩)이길 원한다. 그래야 보기 좋고 버디버드도 노출된다.
26. 사진을 올리는 사용자로서, 내 사진이 서버로 전송·저장되지 않고 내 기기 안에서만 처리되길 원한다. 그래야 사생활이 보호된다.
27. 보호자로서, 카메라 권한을 거부했거나 기기가 지원하지 않으면 갤러리 업로드로 대체할 수 있길 원한다. 그래야 어떤 기기에서도 막히지 않는다.
28. 보호자로서, 네이티브 공유가 안 되는 브라우저에서는 카드 이미지를 저장하고 인스타에 올리는 안내를 받고 싶다. 그래야 데스크톱/구형 브라우저에서도 공유할 수 있다.
29. 공유받은 친구로서, 공유된 결과(또는 링크)를 보고 나도 테스트를 시작할 수 있는 경로를 찾고 싶다. 그래야 바이럴 루프가 이어진다.

### 앱 유도 (전환)

30. 잠재 사용자로서, CTA를 누르면 내 기기(iOS/Android)에 맞는 스토어로 자동 분기되길 원한다. 그래야 헤매지 않고 설치할 수 있다.
31. 버디버드 팀으로서, 어느 유형/단계에서 CTA 클릭과 설치가 일어나는지 측정하고 싶다. 그래야 바이럴 효율을 개선할 수 있다.

### 접근성 · 품질

32. 키보드 사용자로서, 선택지와 버튼을 키보드만으로 조작할 수 있길 원한다. 그래야 누구나 이용할 수 있다.
33. 스크린리더 사용자로서, 문항·선택지·결과가 의미 있게 읽히길 원한다. 그래야 비시각 사용자도 결과를 얻는다.
34. 저사양 모바일 사용자로서, 페이지가 빠르게 로드되길 원한다. 느리면 시작 전에 이탈하기 때문이다.

## Implementation Decisions

### 화면 구조 / 라우팅

- 세 개의 surface: **안내(Intro)**, **문항(Test)**, **결과(Result)**. 모바일 우선(mobile-first) 단일 페이지 경험.
- 결과는 **공유 가능한 상태**여야 한다. 결과 유형(또는 선택 답안)을 URL에 인코딩해, 링크를 열면 동일 결과가 재구성되도록 한다. 결과 URL은 바이럴 진입점이며, 거기서 "나도 테스트하기"로 안내 페이지로 보낸다.
- 새로운 Next.js(이 저장소 버전)의 라우팅/렌더링 규약은 학습 데이터와 다를 수 있다 — 구현 전 `node_modules/next/dist/docs/`의 관련 가이드를 먼저 확인한다(AGENTS.md 지침).

### MBTI 산출 로직

- 정식 **4축 16유형**. 축: E·I, S·N, T·F, J·P.
- **축당 3문항, 총 12문항**으로 한다. 홀수 문항으로 축별 동점(타이)을 원천 차단한다.
- 각 선택지는 정확히 한 축의 한쪽 글자에 1점을 가중한다. 축별 다수 글자가 그 축의 결과 글자가 된다.
- 산출은 **순수 함수**로 분리한다: 입력은 답안 배열, 출력은 유형 코드 + 축별 점수. 부수효과·DOM 의존 없음(테스트 seam).

    ```
    computeResult(answers: Choice[]) -> { type: TypeCode, axisScores: Record<Axis, {left:number, right:number}> }
    // 12개 답안 → 축별 집계 → 각 축 다수 글자 결합 → 4글자 TypeCode
    // 문항이 축당 홀수(3)이므로 타이 불가. 답안 누락 시 결과 산출 거부(불완전 입력 검증).
    ```

- 문항 데이터(질문 문구, 두 선택지, 각 선택지의 축/방향)와 유형 데이터(유형명, 리포트 카피, 대표 이미지)는 **콘텐츠 데이터 모듈**로 분리한다. 콘텐츠는 코드와 독립적으로 교체 가능해야 한다.

### 상태 관리

- 답안 진행 상태는 **클라이언트 전용**. 서버 영속화 없음.
- 진행 중 상태는 메모리로 들고, 결과 단계에서 URL에 인코딩한다. 새로고침 복원 정책은 명시적으로 정한다(세션 유지 또는 명확히 처음부터 — 단, 답이 조용히 소실되지 않게).

### 안내 페이지

- 16유형 앵무새 이미지를 **자동 진행 캐러셀**로 노출. 수동 좌우 컨트롤 제공.
- `prefers-reduced-motion` 시 자동 진행을 멈추고 수동 조작만 허용한다.
- "테스트 시작하기" CTA는 중앙 하단. 앱 유도(App CTA) 진입점도 함께 노출.

### 문항 페이지

- 한 번에 1문항 + 2선택지. 선택 즉시 자동으로 다음 문항 전환(별도 다음 버튼 없음).
- **전환 애니메이션**: "풀숲을 헤치고 이동하는" 결. 컴포지터 친화 속성(`transform`/`opacity`/`clip-path`)만 사용하고 레이아웃 유발 속성은 피한다. `prefers-reduced-motion` 시 즉시 전환으로 대체.
- 진행률 표시. 직전 문항으로 되돌아가 수정 가능. 마지막 답안 직후 결과로 자동 이동.

### 결과 페이지 · 결과 카드

- 유형별 대표 이미지 + 리포트 카피 + "다시하기"/"공유하기" 버튼.
- **사진 입력**: 카메라 직접 촬영과 갤러리/파일 업로드를 **모두** 지원. 카메라 미지원·권한 거부 시 업로드로 자연스럽게 폴백.
- **결과 카드 생성**: 클라이언트에서 **Canvas**로 정사각 카드(권장 1080×1080) 합성 — 사용자 사진 + 유형 + 카피 + 버디버드 브랜딩/CTA. 카드 템플릿은 유형별로 달라질 수 있다.
- **사진 처리는 100% 클라이언트**에서. 사진을 서버로 전송·저장하지 않는다(개인정보 보호 — User Story 26).

### 공유

- **Web Share API 네이티브 공유**: 생성된 카드 이미지를 `File`로 만들어 `navigator.share({ files })`로 공유. `navigator.canShare({ files })`로 사전 기능 탐지.
- **폴백**: 네이티브 파일 공유 미지원 시 카드 이미지 다운로드 + "인스타에 올려주세요" 안내.
- 웹은 인스타 피드 직접 게시 API가 없다 — 직접 게시는 시도하지 않는다(OS 공유 시트를 통한 사용자 주도 공유).

### 앱 유도 (App CTA)

- **딥링크 서비스(OneLink/Branch 등) + 스토어 링크** 조합. 단일 링크가 iOS/Android로 분기하고 설치 후 컨텍스트(예: 유입 유형)를 전달할 수 있게 한다.
- CTA는 **안내 페이지와 결과 페이지 모두**에 배치.
- 실제 딥링크/스토어 URL은 확정 전까지 **단일 설정 상수(placeholder)** 로 관리해 한 곳에서 교체 가능하게 한다. (확정값 필요 — Further Notes 참조)

### 분석 / 트래킹

- **클라이언트 사이드 이벤트 트래킹**(서버 없음). 퍼널 핵심 이벤트: 테스트 시작, 문항별 응답, 완료(유형 도출), 사진 첨부, 공유 성공/폴백, App CTA 클릭.
- 구체 도구(GA4/Amplitude 등)는 미확정 — 이벤트 스키마를 먼저 정의하고 어댑터로 주입한다. 트래킹 백엔드 구축은 본 PRD 범위 밖.

### 비기능 / 품질

- 모바일 우선, 정적 배포 가능 구조. 성능 예산은 마이크로사이트 기준(웹 규칙)에 맞춘다 — 빠른 FCP/LCP, 작은 번들.
- 접근성: 시맨틱 마크업, 키보드 조작, 스크린리더 레이블, reduced-motion 준수.
- 콘텐츠 i18n는 MVP에서 한국어 단일로 가정(다국어는 범위 밖).

## Testing Decisions

**단위/스냅샷 등 테스트 코드는 작성하지 않는다.** 검증은 전적으로 **agent-browser
E2E + 시각 스크린샷**으로 한다. 좋은 검증은 **외부로 관찰 가능한 행동**을 확인하고,
내부 구현 세부(특정 DOM 구조, 함수 시그니처)에는 결합하지 않는다.

### 검증 수단과 대상

- **사용자 플로우 (E2E, agent-browser — 최우선)**: 안내 → "테스트 시작하기" → 12문항 자동 진행 → 결과 도출까지의 핵심 경로를 라우트 단위로 구동한다. 고정 타임아웃 대신 준비 신호(`document.fonts.ready`, 가시 요소)로 대기.
- **MBTI 산출 검증 (E2E)**: 알려진 선택지 조합으로 플로우를 끝까지 구동했을 때 결과 페이지에 기대 유형이 표시되는지로 확인한다. (순수 함수 `computeResult`는 구현상 분리하되, 검증은 화면 결과로 한다.)
- **결과 URL 재구성 (E2E)**: 결과 URL을 직접 열면 동일 유형이 재구성되는지(공유 진입점) 확인한다.
- **공유 동작 (E2E)**: `navigator.share`/`canShare`를 브라우저 컨텍스트에서 가로채(stub) 네이티브 공유 분기와 다운로드 폴백 분기가 올바른 인자(파일 포함)로 동작하는지 확인한다.
- **시각 회귀 (스크린샷)**: 안내 캐러셀, 문항 전환, 결과 카드를 320/375/768/1024/1440에서 캡처. reduced-motion 동작도 확인.
- **접근성 (자동 + 키보드)**: 자동 접근성 점검 + 키보드만으로 전체 플로우 완주.

### Prior art

- 현 저장소에는 아직 검증 인프라가 없다(그린필드). 본 PRD가 첫 도입 지점이며,
  **agent-browser E2E 하니스 셋업**을 첫 슬라이스로 분리한다(단위 테스트 러너는 도입하지 않는다).

## Out of Scope

- 사람 사용자 본인의 MBTI 테스트(대상은 어디까지나 "앵무새").
- 결과·사진·답안의 서버 저장 및 백엔드 데이터베이스.
- 인스타 피드로의 **직접 자동 게시**(웹 API 부재 — OS 공유 시트를 통한 사용자 주도 공유만).
- 동적 OG 이미지 서버 렌더링(유형별 정적 OG로 대체; 동적 렌더는 후속 고려).
- 다국어(i18n) — MVP는 한국어 단일.
- 트래킹 백엔드·대시보드 구축(클라이언트 이벤트 전송까지만).
- 사용자 계정/로그인, 결과 히스토리 보관.
- 버디버드 앱 자체의 변경.

## Further Notes

- **확정 필요한 콘텐츠 자산**: 12개 문항 문구와 선택지(각 선택지의 축/방향 매핑 포함), 16유형 리포트 카피, 유형별 대표 이미지, 결과 카드 템플릿 디자인. 콘텐츠는 코드와 분리된 데이터로 들어오며, 확정 전까지 플레이스홀더로 진행 가능.
- **확정 필요한 링크**: App CTA의 딥링크 서비스(OneLink/Branch 등) 발급 링크와 iOS/Android 스토어 URL. 단일 설정 상수로 관리.
- **확정 필요**: 분석 도구 선택(GA4/Amplitude 등). 이벤트 스키마는 먼저 정의 가능.
- **결과 카드 규격 제안**: 1080×1080 정사각(인스타 피드 기준). 스토리(1080×1920) 변형은 후속.
- **새로고침/세션 복원 정책**: 문항 진행 중 새로고침 시 동작(이어하기 vs 처음부터)을 구현 단계에서 명시적으로 확정한다 — 답안이 조용히 소실되지 않는 것이 원칙.
- 도메인 용어가 안정화되면 본 문서의 Glossary를 `CONTEXT.md`로 승격하는 것을 권장한다.
